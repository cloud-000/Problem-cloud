# Rendering assets

All rendering assets are same-origin and generated by
`bun scripts/vendor-assets.ts`. `prepare` and `build` invoke it with
`--if-missing`; incomplete files or stale icon instances fail the completeness
check. `static/fonts/` and `static/vendor/` remain gitignored.

## Text fonts

Inter uses one variable font per Unicode subset (`300..700`); JetBrains Mono
uses `400..600`. Source Serif 4 retains weight and optical-size variation plus
its separate normal/italic faces. Latin and Latin Extended are retained.

`app.html` preloads only Inter Latin. Practice, Library, and Welcome preload
Source Serif Latin in their page heads. Other pages load serif, monospace,
italic, or extended-subset faces only when their rendered text requires them.
All text faces use `font-display: swap`.

The vendor script removes retired generated font files after writing the new
stylesheet. The service worker also admits only the current shared font names,
so leftover individual-weight copies and the retired icon font cannot enter a
new deployment's precache.

## Icons

`Icon` renders a span containing an SVG `<use>` reference to
`/vendor/material-symbols/<name>.svg#<instance>`. Each file contains both fill
states and any explicit weight, grade, or optical-size instances used in source.
Only displayed icons are requested during foreground rendering; all icon files
are precached for offline use. There is no icon font or font-display delay.
The span retains sizing classes, colors, events, a bindable ref, and accessible
name text. Artwork uses the inherited `fontsize` (one em), independently of the
wrapper box; inline dimensions keep ancestor buttons' generic SVG size rules
from shrinking it. This preserves the former font glyph sizing. The SVG itself is decorative. Use `name="close"`, not text children.

Run after adding an icon or changing an axis instance:

```sh
bun scripts/icon-subset.ts --write
```

The generated manifest lives in
`.cache/render-assets/material-symbols-subset.json`, which is gitignored and
outside `static/`, so it is neither deployed nor precached. It records the
upstream revision, icon names, instance ids, byte sizes, and SHA-256 checksums
for completeness checks and local reuse. It is a cache, not a lockfile: the
source scan defines required icons and `ICON_REVISION` in the generator pins
the artwork. A clean install regenerates both SVGs and metadata; deleting this
cache simply makes the next vendor check regenerate them. Google font-ligature
aliases are resolved through the pinned revision's codepoint table. The Apache license is vendored beside
the artwork. SVG output contains only validated path geometry.

Names can come from data objects, ternaries, or other dynamic selections. The
scanner conservatively includes known names from source literals, excluding
comments and test files. Extra names add offline storage but no global download.
Explicit numeric axes must be static, on an Icon with a static name, so the
vendor step can generate the exact artwork. Dynamic `fill` is supported. Unlike
the former variable font, arbitrary continuously varying numeric axes are not
supported. Current app uses are preserved: check at optical size 20, expand_more
at optical size 20, and mark_email_unread at weight 500.

## Verification

`bun run check`, `bun test`, and `bun run vendor:check` validate types, local
references, checksums, instance coverage, shared font URLs, and offline cache
eligibility. Production cold-load comparisons use `bun run perf:measure` against
an explicitly started production build/preview. The harness blocks service
workers; its font bucket excludes KaTeX and includes font CSS.

## Cloudflare Pages routing

The adapter's `routes.exclude` in `vite.config.ts` groups `/vendor/*`,
`/fonts/*`, and `/icons/*` under directory rules. Do not replace these with
`<files>` or `<all>`: those expand every SVG into a separate exclusion and
exceed Pages' 100-rule limit. Build artifacts, prerendered pages, and redirects
retain their adapter placeholders; root static files and the service worker
have explicit exclusions. Add an exclusion when introducing a new root asset.
App pages, auth routes, and API endpoints continue to invoke functions.
